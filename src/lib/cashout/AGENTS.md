# Cash-out

- TSD cash-out key is profile-scoped (src/lib/cashout/api-key.ts): link claims write to the wallet captured before any await, records keep only an 8-hex fingerprint, the legacy device-wide key migrates once (marker; a reappearing unprefixed key is the default wallet's), and cash-out orders re-check wallet+key fingerprint before signing. Why: an account token must never cross wallets.
- Cash-out path is chosen by `chooseCashoutPath` (src/lib/cashout/one-time.ts): only a payout equal to the account's saved address uses the permanent inbox; any other address is a one-time `/cashout/orders` order. Its refund address is the Omni sender (`pickOmniSender`, same rule as the send) and the send refuses a different sender; the server reads the key's own permanent inbox itself and the reply is verified there and on the device (fresh legacy T… deposit, not the permanent inbox or a wallet-owned address, echoed account inbox agrees, echoed payout, exact decimal amount carried as a string, Ethereum, `ONE_TIME_EXPIRY_MARGIN_MS` left). Right before signing the wallet re-polls the order (or re-reads the saved address on the inbox path); the deposit notice is sent only for the permanent inbox. `/cashout/payout-address` is a separate explicit action and never precedes a deposit. Why: the permanent inbox always pays the saved address, a missing refund address defaults to that inbox, and TSD Swap only accepts notices for it.
- The TSD deposit notice is signed only after the server checks the key's own account (permanent inbox + saved payout) and the on-chain TSD Simple Send (txid, property 39, exact amount, inbox as reference) in `deposit-notice.ts`. Why: our server signature must never vouch for caller-supplied facts.
- Buying TSD with stablecoins (`src/lib/cashout/mint.ts`) pays only the contracts pinned in `MINT_SOURCES` from TSD Bridge's deposit-watcher list (`TSD_BRIDGE_CONTRACT_PIN`); while its `writtenConfirmation` is null, `availableMintSources` offers nothing (UI and server), so publishing cannot enable the route; once the feed or an order publishes contracts, a mismatch is refused. The order is opened with the member's own key, verified on the server and again on the device (`confirmLockedMintOrder`: exact request, pinned contract, deposit not wallet/contract/zero and unused by any earlier local order, more than `MINT_EXPIRY_MARGIN_MS` left, checked again after the confirmation prompt; fee read only from `mintFeeBps`), recorded locally at Review (`mint-history.ts`; identical open orders are reused, superseded ones abandoned and never polled), re-polled before signing (echoed recipient/token/contract checked when present), and signed only as the exact ERC-20 `transfer(deposit, amount)` via `assertMintTransferRequest` (chain id required, never optional); "sent" means a successful receipt. Late-deposit wording appears only from `TSD_BRIDGE_LATE_DEPOSIT_POLICY` (TSD Bridge's written words). Selling TSD hands off to the audited Send cash-out. Why: mint deposit addresses rotate, the bridge credits by contract and never pays in its last hour, so a late, reused or wrong-token payment can be lost.
- TSD cash-outs are recorded per wallet in `cashout-history.ts` as "sending" (locally computed txid) right before broadcast and upgraded to "sent" after (`broadcastRecordedCashout`; public facts + key fingerprint, never the key; status-less legacy rows read as sent); the desktop Swap history (`src/components/desktop/SwapHistory.tsx`) merges it with swap-history and paid mint records and polls TSD orders only with the key whose fingerprint matches. Why: one read-only history without moving keys or adding signing paths, and a broadcast error never proves a payment is absent.
