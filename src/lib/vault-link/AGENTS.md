# Vault wallets (offline signing via HME Vault)
- THORChain desktop preparation lives in thor-swap.ts and never broadcasts; UTXO deposits precede first-input-address change and memo, every previous output and genuine SIGHASH_ALL signature is checked. EVM hm-thor-swap is a proposed distinct protocol, not transfer-only hm-evm-tx. Why: current HME Vault rejects swap memos/approvals, so coordinated review must precede release.
- TSD single sends use the dedicated property-39 builder with legacy TXC address #0 as sole input holder and change destination; broadcast requires frozen PSBT equivalence, genuine SIGHASH_ALL signatures and fresh profile/pairing/session/unspent/balance checks. Why: Omni reference selection can redirect tokens when native HD change rules are reused.
- TSD receiving refuses non-legacy pairings; fee preparation shares builder input selection before downloading previous transactions. Why: receiving must remain spendable and unused coins must not cause unnecessary provider work.
- TXC spent-input checks use fresh transaction-wide `/outspends` with an exact-index boolean; missing or malformed results fail closed. Why: the singular endpoint serves HTML without browser access headers.
- QR playback controls operate on existing frame strings; receiver dots use copied one-based collector indexes, never inferred counts or sender acknowledgements. Why: replay missing pieces without changing signing bytes or claiming the offline Vault received them.

- Serialize Vault PSBT bytes with bounded, non-spread Base64 encoding; never use dependency toBase64 for browser preparation. Why: legacy previous transactions can exceed the browser argument stack limit without changing signing bytes.

- EVM send routes resolve Vault balances only from the paired public address, never the random wrapping root; native and ERC-20 sends use restricted Vault intents and verify the complete signed transaction before broadcast. Why: displaying or signing for the wrapping anchor targets a different, empty wallet.
- LTC/DOGE deposit-address swaps use paired scans, the paired EVM payout address and unsigned PSBTs; signed results must match every input/output, memo/change, version and locktime before broadcast. Why: the wrapping anchor cannot fund or receive Vault swaps.
- Vault profiles are envelope `mode: "vault"` — random anchor like keyonly, no seed; watch-only account xpubs live in `pairing.ts` (scoped `hme.vault-link.v1`). Why: unlock/session/switch machinery stays byte-identical and no key material is ever stored.
- Vault profiles render the normal home screen (`wallet.index.tsx`): chain scans come from `vaultAccountSnapshot` (`snapshot.ts`) instead of the seed, and Send/Receive use `VaultBottomActions`, which builds unsigned PSBTs (`psbt-build.ts`) or `hm-evm-tx` intents (`evm-intent.ts`) shown as HMQR2 animated QRs (`qr-parts.ts` — must stay byte-compatible with HME Vault's `src/lib/signer/qr-parts.ts`); only signed hex comes back for verify + broadcast. `VaultHome` is only the unpaired fallback. Why: same experience up to signing, and the online wallet must never ask for an xprv.
- Wallet factory helpers (createVaultWallet etc.) only build the UnlockedWallet; saving is always saveWalletToNewProfile/saveWallet by the caller. Why: a factory that saves writes to the currently active profile slot and overwrites that wallet (this destroyed a seed envelope once).
- Ordinary UTXO sends and swaps share verifySignedAgainstPsbt before broadcast, binding every non-signature field; recipient-only checks are secondary. Change uses highest historical used change index plus one; malformed scan collection resets visibly without closing capture. Why: protect remaining funds and permit safe animated-frame recovery.
- TSD on receive addresses #1+ is gathered by tsd-gather.ts in one Vault-signed transaction per holder: holder coins first, then only-needed #0 fee coins, outputs [OP_RETURN property-39 whole balance, address #0]. Why: TEXITcoin Omni Class C takes the sender from the first input, so #0 fee coins after the holder cannot become the sender.
- Vault round-up (evm-roundup.ts, desktop VaultRoundUp) only moves Ethereum/Base stablecoins and leftover ETH from account-xpub addresses to paired #0 through Vault `sweep-batch` (own #0 only, ≤25) and fee top-ups through the pinned `native-disperse` contract, paying only the Vault's own derived addresses (runtime code checked at prepare and before broadcast); both kinds are listed in REVIEWED_VAULT_BATCH_SURFACES. TSD is then bought with one ordinary order per coin from #0. Why: TSD Bridge settles each order against one transfer, batches can only pay the Vault's own #0, and Vault itself does not yet refuse foreign disperse recipients.
- Round-up "pay fee money from another wallet" (externalTopUpList) re-derives every listed address from the paired account xpub and rounds the 1.5× top-up up to 6 decimals; it signs nothing. Why: a copy-paste funding list must only ever name the Vault's own addresses.
