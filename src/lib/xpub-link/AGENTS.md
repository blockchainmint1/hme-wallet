# Trading links
- Coins the wallet doesn't support (delegate-keys.ts) are shared only when the site lists them, only in access links, at the same branch, standard xpub/xprv (SOL raw SLIP-0010, ADA Icarus, XMR Trezor-method spend key), and are never sent or swept; only the desktop Seeds Pocket shows their address #0 and chain-read balance (src/lib/seeds/extra-addresses.ts, pinned to Seeds' vectors). Why: the site trades them; approve mode can't sign them.
- The extra-coin list is fixed in wallet code; sites only choose from it, and unknown optional coins are skipped. Why: a new key type needs reviewed derivation code and an audited release.
- Extra coins need the site's exact `format` string to match the wallet's method; otherwise skipped. Why: a changed method must never produce a key the site doesn't expect.
- One link record per site + pocket; relinking replaces it, and a pocket that gave access can't be relinked as approve-only. Why: stale duplicates let revoke sweep a live pocket, and a site that saw the keys keeps them.
- An update to an access link must keep every coin the replaced record holds (core and extra); fewer coins or a changed key label refuses the update. Why: the record drives Revoke's sweep and warnings, so a dropped coin's key would stay with the site unseen.
- Revoke uses the in-app dialog; when extra coins were shared it needs a ticked "moved them out" acknowledgement. Why: it's the member's last cheap moment to rescue coins the wallet can't move.
- Trading links refresh honest.money's signed list right before reading and before sharing; an unreachable list stops with "couldn't reach honest.money" and never replaces the last good grants. Why: an outage must not read as "not approved" or wipe or grant spending access.
- Desktop Seeds Pocket (/desktop/seeds) shows only coin names, chain-read balances and each core coin's pocket address #0 (never extended public keys or the full address list), and moves back only to the wallet's own #0. TXC Move back stays put while TSD is on the pocket or unknown; "Move TSD back" (src/lib/seeds/pocket-tsd.ts) sends each holder's whole TSD to the main TSD address #0, holder coins first, all input TXC to that same #0 as the only non-data output. With no local link record, it shows a pocket only at a branch the fresh verified registry reserves for Seeds that has chain activity; such a found pocket never gets a made-up link record and has no Revoke. Why: an extended public key exposes every pocket address, a TXC sweep would strand the TSD without a fee, extra coins stay blind, and Revoke's sweep and warnings rely on the real record.
- A revoked trading branch is never handed to another site, but the same site may link it again on the same path, "Give access" only, with a note that it reuses the revoked pocket; a branch retired by an old build without a recorded site stays retired. Why: the member chooses to undo a revoke, and that site already kept the old keys, so approve-only would misstate what it can do.
- Seeds' accept-and-hold coins (XLM/TON/SUI, hold-coins.ts) are linked only when SEEDS_HOLD_COINS_LIVE is true, gating both the link reader and the relay; they never appear in the Seeds Pocket view. Why: Seeds ships first, and live Seeds refuses a whole link containing paths it doesn't yet accept.
