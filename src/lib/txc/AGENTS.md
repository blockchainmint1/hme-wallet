# TXC
- Desktop send-to-many (/desktop/bulk-send, src/lib/txc/bulk-send.ts): TXC is one multi-output tx; Omni tokens use type-7 batches of 7 from the single holder address, chained on change, stopping at the first failure. Why: TXC node relays one 80-byte OP_RETURN per tx and Omni sender must be unambiguous.
- Every TXC signing via buildAndSignTx refuses fee rates at or above TXC_MAX_FEE_RATE; send-to-many shows "Tokens delivered" only after omni_gettransaction says valid, and saves progress per wallet fingerprint until settled. Why: a confirmed TXC tx can still carry a rejected token transfer, and reloads must not hide partial runs.
- The optional BIP39 passphrase uses PassphraseField (no password-manager autofill: text box masked by CSS, ignore markers, read-only until touched); a filled passphrase blocks import until the member confirms that exact value or clears it, and the backup page shows whether one is set. Why: a silently autofilled passphrase turns the same words into a different, empty wallet.
- TXC fee rates come only from txcFeeRate (src/lib/txc/fees.ts): live estimate floored at the node minimum (1 sat/vB), cautious fallback only when the estimate is unavailable; legacy inputs are sized at 149 vB and buildAndSignTx refuses fees under 1 sat per signed vbyte. Why: a fixed floor overcharged members, and a 148-vB estimate can fall one sat short of the relay minimum.
- A node refusal (400/422 with text) plus an exact 404 lookup is a failure that releases reservations; other failures stay uncertain. Check again (journal, bulk, gather) and the card status poll release only when the txid is 404 AND every reserved input is unspent; malformed journal entries are skipped. Attempts younger than two minutes always recheck unknown; journal/bulk records save their attempt time and legacy records receive a one-time fresh wait. Why: explorer lag must not release a transaction already in the node's mempool, and no coins or cards stay locked forever.
